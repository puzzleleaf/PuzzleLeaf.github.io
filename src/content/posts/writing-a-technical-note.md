## 한 문장으로 먼저 답하기

이 글은 **기술 글의 작성 형식을 보여주는 샘플**입니다. 도입부에서 어떤 문제를 다루고 어떤 결과를 얻었는지 짧게 밝히면 독자가 자신의 상황에 필요한 글인지 판단할 수 있습니다.

> 예시: 특정 입력에서 발생하는 오류를 재현하고, 입력 검증을 추가해 같은 오류가 발생하지 않는 것을 확인했습니다.

실제로 확인한 내용만 적고, 아래 형식은 자신의 경험으로 바꿔 작성하세요.

## 실행 환경을 남기기

코드의 동작은 버전과 환경에 따라 달라질 수 있습니다. 다른 사람이 재현할 수 있도록 확인한 조건을 적습니다.

| 항목 | 작성할 내용 |
| --- | --- |
| 언어·엔진 | 실제 사용한 버전 |
| 운영체제 | 재현에 영향을 주는 환경 |
| 발생 조건 | 입력, 설정, 재현 순서 |
| 기대 결과 | 원래 기대한 동작 |

## 최소한의 예제로 설명하기

주제와 관련 없는 코드를 줄이면 핵심을 읽기 쉽습니다. 예를 들어 다음 코드는 빈 입력을 명시적으로 처리하는 간단한 예시입니다.

```ts
function getDisplayName(name: string): string {
  const trimmed = name.trim();
  return trimmed || '이름 없음';
}
```

예시 코드는 설명을 돕는 용도입니다. 실제 문제를 해결한 코드와 검증 결과는 별도로 적습니다.

## 결과와 한계를 함께 남기기

어떤 입력을 확인했는지, 원래 문제가 사라졌는지, 아직 확인하지 않은 조건이 무엇인지 적습니다. 성능 수치를 쓸 때는 측정 환경과 방법도 함께 남깁니다.

## 출처와 수정일 관리하기

공식 문서를 링크하고, 인용한 정보와 직접 확인한 결과를 구분하세요. 글을 수정했다면 frontmatter의 `updated`를 실제 수정 날짜로 설정하면 됩니다.

```yaml
updated: 2026-10-17
```
